# Sub Agent

在 Web UI 按「Sub Agent」查看目前 Workspace 的任務，按「建立 Sub Agent」填寫工作與必要背景。子任務沿用主對話當下的模型與思考強度，但有獨立的 Pi Session；不會自動取得整份主對話。

主 Agent 也可透過 `subagent` 工具建立、列出、查看及取消自己的子任務。工具只由 Web 啟動的主 Pi 載入，透過私有 Unix socket 連接任務管理器。瀏覽器不取得此連線或模型憑證；子 Pi 不載入 extensions，也不繼承該 socket，避免遞迴委派。

| 類型 | 執行方式 |
|---|---|
| 閱讀與分析 | 在原 Workspace 執行，只提供 `read`、`grep`、`find`、`ls`。這是工具限制，不是作業系統沙箱。 |
| 程式開發 | 需要已有 commit 的 Git repository。從目前已提交的 HEAD 建立獨立 worktree 與 `pi/subagent/<id>` 分支；原目錄未提交的變更不會帶入。 |

程式任務沿用執行環境的 Git 身分，指示子 Agent 在獨立 worktree 工作，不自行 commit、push 或 merge。面板會顯示來源 commit、分支、工作目錄與結果；整合前仍需檢查 diff 和測試。任務結束或取消不會刪除 worktree。

點「填入主對話草稿」可把結果帶回父 Session；會先切回父對話，保留既有草稿，不自動送出。主 Agent 透過工具取得的結果也應視為待核對的報告。

最多同時執行 3 個子任務，另可排隊 20 個。每個任務預設上限 15 分鐘、100 則助手訊息與 60000 字元保存輸出；到達上限會停止並顯示原因。模型錯誤與需要互動的情況會明確停止，不自動改寫或重送。

資料位於 Web 資料目錄的 `subagents/`，資料夾權限 0700、工作索引 0600，保留最近 100 個任務的狀態與結果。Pi Session 與 worktree 各自存放；歷史索引淘汰不會刪除程式變更。服務重啟後，原本未完成的任務標為中斷，需重新建立才會再執行。

自動化驗證使用臨時 workspace、Git repository、真 Pi 與本機假模型服務，涵蓋主 Agent 委派、工具範圍、模型選擇、並行、取消及重啟狀態。測試不代表實際模型的程式品質或任務成功率。
